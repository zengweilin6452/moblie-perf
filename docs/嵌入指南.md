# mobile_perf 嵌入指南（宿主接入）

面向 mobile-auto（及未来测试平台）把性能采集嵌进自有测试流程。依赖方向见
ADR-0001：宿主 → mobile_perf，本组件零第三方依赖（Python ≥ 3.10），不
import 宿主代码；设备准入由宿主注入 DeviceGate。

## 1. 术语

- **PerfKit**：组件门面（`src/mobile_perf/kit.py`）。`ensure_ready()` 巡检
  自愈；`collect()` 交互式采集窗口；`run_collect()` 定时闭环；`judge()`
  门禁判定；`trend()` 趋势对比；`save_baseline()` 基线入库。
- **DeviceGate**：短事务设备准入协议——只在发起设备命令的短窗口持有设备权，
  采集进行中不持有（与宿主整生命周期租约互补，见 §2）。
- **前台守卫**（默认开启，`PerfKit(foreground_restore=False)` 关闭）：Harness
  的 doctor/perf-start/perf-stop 经 SoloPi 控制面启动，会抢被测应用前台；
  组件在每次这类命令后检测漂移并还原为采集前组件，事件（kind=foreground）
  随 run/巡检入库。

## 2. 注入 PerfKit 与 gate 适配

```python
from mobile_perf import PerfKit
from mobile_perf.store import PerfStore

kit = PerfKit(
    serial="749622c9",          # 必填
    runs_dir="...", db_path="...",           # 建议显式，避免落进包仓库
    gate=my_gate,               # 见下；不传则默认 FileLockGate（对等参与锁文件协议）
    device_profile="Pixel7-Android14",       # 判读口径绑定，建议按机型+OS 大版本命名
)
```

宿主持有整生命周期租约时（如 mobile-auto 的 DeviceSession），注入适配器
把租约桥接为 DeviceGate——**嵌入模式重入放行**，不会与宿主互锁死锁：

```python
# mobile-auto 侧参考实现：src/mobile_auto/_perf_gate.py
from mobile_auto._perf_gate import PerfDeviceGate

gate = PerfDeviceGate(leases={serial: session._lease})   # 宿主租约预置
kit = PerfKit(serial=serial, gate=gate, ...)
```

未预置租约时适配器按短事务 acquire/release，被其他进程占用抛
`GateBusyError`（fast-fail，不排队；重试是宿主策略）。

## 3. 采集窗口（两种形态）

交互式（UI 驱动期间采集，设计方案 §6.2）：

```python
with kit.collect(target="tv.danmaku.bili", items=["CPU", "FPS", "Memory"],
                 host_run_id="pytest-20261025-001") as scope:
    drive_ui()                     # 宿主驱动被测应用
    scope.mark("scroll_done")      # 打标进统一时间轴
report = scope.report              # with 退出即 finalize（停止→pull→归档→入库→报告）
```

- 块内异常也会照常收口（端侧录制不悬挂，报告仍产出）；
- `kit.run_collect(target=..., items=..., duration_s=...)` 是同一条链路的
  定时收口特例（CLI 即用它）。

门禁判定（三态 passed / failed / not_tested；阈值归宿主，不入库）：

```python
from mobile_perf import JudgeSpec

kit.save_baseline(report, "bili-home-v3")        # 一次，基线绑定 device_profile
verdict = kit.judge(report, JudgeSpec(
    baseline="bili-home-v3",
    thresholds={"mem_pss_mb": ("lt", 220, "fail"), "fps_frame": ("gt", 50, "fail")},
))
verdict.verdict            # passed / failed / not_tested
verdict.checks             # 逐指标明细（median/op/threshold/baseline/样本数）
```

`not_tested` 的触发：报告无聚合、基线不存在、device_profile 不匹配、样本
数低于下限（默认 10，`JudgeSpec.min_samples` 可覆盖）。样本口径见
`metrics.py` 指标字典（canonical key 全组件唯一）。

## 4. pytest 钩子 `--mobile-perf`

本包装后（entry point `pytest11: mobile-perf`）即提供 `perf` fixture，形态
对称 mobile-auto 的 `--mobile-evidence`。opt-in：不开旗标零行为。

```python
def test_home_scroll(device, perf):
    with perf.session("tv.danmaku.bili", items=["CPU", "Memory"]) as scope:
        device.launch_app("tv.danmaku.bili"); device.swipe_up(5)
        scope.mark("scroll_done")
    # 退出即 finalize；指定 baseline 时自动 judge
```

- 结论经 `report.sections`（标题 `mobile-perf`：runId/durationS/verdict/
  逐检查项）进 JUnit/HTML 等报告；阈值判 failed 不拉低用例结论——由宿主
  对 `perf.results[-1].verdict` 断言决定；
- `perf.results` 为本用例全部采集结果（`PerfResult.report/.verdict`）；
- serial / 采集项 / 基线 / 阈值经 CLI 或 ini：

  | 参数 | CLI | ini |
  |---|---|---|
  | 开关 | `--mobile-perf` | — |
  | serial | `--mobile-perf-serial` | `mobile_perf_serial` |
  | 采集项 | `--mobile-perf-items CPU,FPS,Memory` | `mobile_perf_items` |
  | 基线 | `--mobile-perf-baseline NAME` | — |
  | 阈值 | `--mobile-perf-threshold METRIC:OP:LIMIT:LEVEL`（可重复） | `mobile_perf_thresholds`（逗号分隔） |
  | 归档目录 | `--mobile-perf-runs-dir` | — |
  | store 路径 | `--mobile-perf-db` | — |

  OP ∈ lt/le/gt/ge，LEVEL ∈ fail/warn。session 调用参数
  （`perf.session(target, items=..., baseline=..., thresholds=...,
  min_samples=...)`）优先于 CLI/ini。

- **kit 替换点**：`mobile_perf_kit` fixture（session 级）是唯一构造入口，
  宿主 conftest 同名覆盖即可注入自家 adb 路径、DeviceGate 适配器、
  device_profile 与共享 store——mobile-auto 的真机联动用例
  （`tests/device/test_perf_linkage_device.py`）即按此覆盖。

## 5. 并发（pytest-xdist）

- 设备准入：同设备两 worker 并发采集 → 后到者在首个设备命令上收到
  `GateBusyError`（fast-fail，实测秒级完成、不死锁）；不同设备 → 各自
  独立成跑；
- store：SQLite WAL + busy_timeout 5s，多进程并发首连与写入安全
  （journal_mode 切换竞争已内置重试）；
- runs 目录建议按 worker 分目录（mobile-auto 池化的
  `worker_artifacts_dir` 即此语义），store/lease 目录可共享。

## 6. 已知边界

- 非本机 Windows 登录用户之外锁协议无效；非 Windows 平台 gate 降级
  passthrough 并告警；
- FPS 采集首轮可能触发 SoloPi 告知框（自编译 1.0.3.1 + 弹窗开关已缓解，
  无人值守路径经 M2 验收）；
- 宿主需自行保证：同一 serial 上的 UI 自动化与采集命令经同一 gate/租约
  序列化（嵌入模式即满足）。
